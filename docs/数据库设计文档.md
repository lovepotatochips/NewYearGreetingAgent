## 设计概述

### 设计原则

1. **规范化设计**：遵循第三范式，减少数据冗余
2. **性能优先**：合理使用索引，优化查询性能
3. **可扩展性**：预留扩展字段，支持未来功能
4. **数据完整性**：使用外键约束保证数据一致性
5. **安全性**：敏感数据加密存储

### 设计目标

| 目标 | 指标 | 说明 |
|------|------|------|
| 响应时间 | <100ms | 单次查询响应时间 |
| 并发支持 | 1000+ | 支持并发用户数 |
| 数据容量 | 100万+ | 支持数据量 |
| 扩展性 | 良好 | 支持水平扩展 |
| 可维护性 | 高 | 易于维护和升级 |

## 数据库选择

### SQLite（开发环境）

**优势**：
- 零配置，开箱即用
- 轻量级，单个文件
- 跨平台支持
- 适合开发和测试

**劣势**：
- 不适合高并发
- 不支持分布式
- 功能相对简单

**适用场景**：
- 开发环境
- 小型应用
- 原型验证

---

### MySQL（生产环境）

**优势**：
- 高性能，支持高并发
- 成熟稳定，社区活跃
- 支持主从复制
- 功能丰富

**劣势**：
- 需要配置和部署
- 资源占用较大

**适用场景**：
- 生产环境
- 大型应用
- 高并发场景

## 表结构设计

### 1. 用户表（users）

#### 表名

`users`

#### 表说明

存储用户基本信息和会员状态。

#### 字段定义

| 字段名 | 数据类型 | 长度 | 允许空 | 默认值 | 约束 | 说明 |
|--------|----------|------|--------|--------|------|------|
| id | INTEGER | - | NO | AUTO | PRIMARY KEY | 用户ID，自增主键 |
| openid | VARCHAR | 100 | YES | NULL | UNIQUE | 微信openid，唯一索引 |
| phone | VARCHAR | 20 | YES | NULL | UNIQUE | 手机号，唯一索引 |
| username | VARCHAR | 50 | YES | NULL | - | 用户昵称 |
| avatar | VARCHAR | 255 | YES | NULL | - | 头像URL |
| membership_type | ENUM | - | NO | 'free' | - | 会员类型：free/vip |
| vip_expire_time | DATETIME | - | YES | NULL | - | VIP过期时间 |
| is_active | BOOLEAN | - | NO | TRUE | - | 是否激活 |
| created_at | DATETIME | - | NO | NOW() | - | 创建时间 |
| updated_at | DATETIME | - | YES | NULL | - | 更新时间 |

#### 索引设计

| 索引名 | 字段 | 索引类型 | 说明 |
|--------|------|----------|------|
| PRIMARY | id | PRIMARY | 主键索引 |
| ix_users_openid | openid | UNIQUE | 唯一索引 |
| ix_users_phone | phone | UNIQUE | 唯一索引 |
| ix_users_membership_type | membership_type | INDEX | 普通索引 |

#### 约束说明

1. **主键约束**：id字段为主键，自增
2. **唯一约束**：openid和phone字段唯一，确保同一用户只能有一个账号
3. **非空约束**：id、membership_type、is_active、created_at字段非空
4. **默认值**：membership_type默认'free'，is_active默认TRUE

#### 存储引擎

- SQLite：默认
- MySQL：InnoDB（支持事务和外键）

#### 字符集和排序规则

- **字符集**：utf8mb4（支持完整Unicode，包括emoji）
- **排序规则**：utf8mb4_unicode_ci（不区分大小写）

## 表关系设计

### 一对多关系

#### users → conversations

- **关系类型**：一对多
- **说明**：一个用户可以有多个对话
- **外键**：conversations.user_id → users.id
- **级联规则**：删除用户时级联删除相关对话

#### users → messages

- **关系类型**：一对多
- **说明**：一个用户可以发送多条消息
- **外键**：messages.user_id → users.id
- **级联规则**：删除用户时级联删除相关消息

#### users → user_greetings

- **关系类型**：一对多
- **说明**：一个用户可以收藏多条祝福语
- **外键**：user_greetings.user_id → users.id
- **级联规则**：删除用户时级联删除相关收藏

#### users → usage

- **关系类型**：一对多
- **说明**：一个用户可以有多条使用记录
- **外键**：usage.user_id → users.id
- **级联规则**：删除用户时级联删除相关使用记录

#### conversations → messages

- **关系类型**：一对多
- **说明**：一个对话可以包含多条消息
- **外键**：messages.conversation_id → conversations.id
- **级联规则**：删除对话时级联删除相关消息

#### greetings → user_greetings

- **关系类型**：一对多
- **说明**：一条祝福语可以被多个用户收藏
- **外键**：user_greetings.greeting_id → greetings.id
- **级联规则**：删除祝福语时级联删除相关收藏

## 索引设计

### 索引设计原则

1. **主键索引**：每个表都应有主键
2. **唯一索引**：确保数据唯一性
3. **外键索引**：优化关联查询
4. **查询索引**：基于常用查询条件
5. **复合索引**：优化多条件查询

```sql
-- 用户表
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

    username VARCHAR(50),
    avatar VARCHAR(255),

    is_active BOOLEAN DEFAULT TRUE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME

    updated_at DATETIME,

    content TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE

CREATE TABLE IF NOT EXISTS greetings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,

);

    user_id INTEGER NOT NULL,
    greeting_id INTEGER NOT NULL,
```

## 安全设计

### 数据加密

#### 密码加密

如果系统支持密码登录，密码应使用bcrypt加密：

```python
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def hash_password(password: str) -> str:
    return pwd_context.hash(password)

def verify_password(plain_password: str, hashed_password: str) -> bool:
    return pwd_context.verify(plain_password, hashed_password)
```

#### 敏感数据加密

手机号等敏感数据应加密存储：

```python
from cryptography.fernet import Fernet

cipher_suite = Fernet(ENCRYPTION_KEY)

def encrypt_data(data: str) -> str:
    return cipher_suite.encrypt(data.encode()).decode()

def decrypt_data(encrypted_data: str) -> str:
    return cipher_suite.decrypt(encrypted_data.encode()).decode()
```

### 读写分离

MySQL支持主从复制，实现读写分离：

```
主库（Master）：负责写操作
从库（Slave）：负责读操作
```

配置示例：

```python
# 主库配置
MASTER_DB_URL = "mysql+pymysql://user:pass@master-host/db"

# 从库配置
SLAVE_DB_URLS = [
    "mysql+pymysql://user:pass@slave1-host/db",
    "mysql+pymysql://user:pass@slave2-host/db"
]
```
